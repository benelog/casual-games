## 실행

빌드 과정은 없다. 다만 `index.html` 을 파일로 직접 열면(`file://`) 동작하지 않는다. 브라우저가
`file://` 에서는 ES 모듈 스크립트와 텍스처·모델 로딩을 보안상 막기 때문이다. 정적 서버로 연다.

```sh
npm start        # python3 -m http.server 8000
```

http://localhost:8000 에서 게임을 고른다.

npm test         # node --test

## 새 게임 추가

1. 최상위에 게임 디렉토리를 만들고 `index.html` 을 둔다. `<head>` 에는 다른 게임처럼 manifest·아이콘·
   `../shared/pwa.js` 줄과 글꼴(Pretendard·Hahmlet)·`../shared/theme.css`·`../shared/game.css`·`style.css` 링크를
   넣는다. 게임의 `style.css` 에는 공통 틀과 다른 점과 게임 고유 색(`--bg`, `--accent`, `--p0` 등)만 적고,
   `theme-color` 는 `--bg` 의 바깥쪽 색으로 맞춘다.
2. 루트 `index.html` 의 `games` 배열에 항목(한/영 제목·설명)을 추가한다. `modes` 로 보여 줄 탭을 정한다:
   혼자서(컴퓨터와 1:1 포함)는 `'solo'`, 여러 사람이 할 수 있으면 `'multi'`, 둘 다면 둘 다 적는다.
   `tags` 에는 분류 필터에 쓰는 `TAGS` 의 키(`sports`·`puzzle`·`card`·`board`·`strategy`)를 하나 이상 적는다.
   새 분류가 필요하면 `TAGS` 에 한/영 이름과 함께 추가한다.
3. 렌더러는 `shared/gpu.js` 의 `createRenderer(THREE, options)` 로 만든다 (아래 모바일 GPU 참고).
4. `npm run thumbs -- <디렉토리>` 로 게임 목록 카드의 썸네일 `thumbs/<디렉토리>.webp` 를 만든다.
   헤드리스 Chrome(`google-chrome`)으로 게임을 열어 3D 장면만 찍는다. 메뉴 뒤 장면이 비어 있으면
   `scripts/thumbs.mjs` 의 `BEFORE` 에 찍기 전에 누를 버튼을 적는다.

## 공통 모듈 (`shared/`)

- **공통 스타일** `shared/theme.css`, `shared/game.css`: `theme.css` 는 게임 목록과 모든 게임이 같이 쓰는 색 토큰
  (`--ink`·`--muted`·`--brass`·`--panel`·`--line`·`--bg`), 글꼴(`--font-body` 는 Pretendard, `--font-display` 는
  제목·큰 숫자용 Hahmlet), 키보드 포커스 표시. `game.css` 는 게임 화면의 공통 틀(바탕, 게임 목록·언어 버튼,
  버튼과 chip, 키 표시, 로딩 화면, 시작 메뉴 카드)이다. 손가락으로 누르는 화면에서는 버튼의 키 이름을 숨기고
  작은 알약 버튼의 누르는 자리를 넓힌다. 글꼴은 jsDelivr 에서 한글을 쓰는 만큼만 받는다.
- **국제화** `shared/i18n.js`: 한국어/영어. 처음에는 브라우저 언어를 따르고(지원하지 않는 언어면 영어),
  각 화면의 언어 버튼(지금 언어 이름이 적혀 있다. 좁은 화면에서는 한·EN 처럼 짧게)을 눌러 목록에서 고르면 localStorage 에 남아 모든 게임에 적용된다.
  게임마다 `js/i18n.js` 에 `{ ko, en }` 사전을 두고 `createT` 로 번역 함수를 만든다. HTML 의 고정 문구는
  `data-i18n` 속성과 `applyI18n(t)` 로 채운다. 언어를 늘릴 때는 `LANGUAGES` 에 한 줄 더하고 각 사전에 그 언어를
  채운다. 빠진 문구는 영어 → 한국어 순으로 물러선다.
- **방문 통계** `shared/analytics.js`: Google Analytics 4. `shared/pwa.js` 가 모든 페이지에 붙인다.
  게임별 방문자는 GA 보고서의 페이지 경로(`/poker/` 등)나 page_view 의 `game` 매개변수(GA 관리 화면에서
  이벤트 범위 맞춤 측정기준 `game` 으로 등록해 두었다)로 본다. GA 속성은 benelog.net 계정의 `casual-games.benelog.net`
  (측정 ID `G-SSZLQ0WJ93`). 측정 ID(`MEASUREMENT_ID`)가 비어 있거나 로컬에서는 보내지 않는다.
- **PWA** `manifest.webmanifest`, `sw.js`, `shared/pwa.js`, `icons/`: 같은 출처 파일은 네트워크를 먼저 쓰고
  안 되면 캐시를, CDN 라이브러리는 캐시를 먼저 쓴다. 한 번 연 게임은 오프라인에서도 열린다.
  껍데기 목록이나 캐시 방식을 바꾸면 `sw.js` 의 `VERSION` 을 올린다.
- **모바일 GPU** `shared/gpu.js`: Pixel 10(PowerVR) 의 Chrome 에서 그림자 맵을 그리다 WebGL 컨텍스트를
  잃고, 그 뒤 Chrome 이 사이트의 WebGL 을 막아 모든 게임이 로딩에서 멈추는 문제가 있었다.
  PowerVR 에서는 그림자를 끄고 픽셀 비율을 1.5 로 낮춘 안전 모드로 그린다(`?safe=1`/`?safe=0` 으로 강제).
  WebGL 을 만들 수 없거나 컨텍스트를 잃으면 로딩 화면에 안내와 다시 불러오기 버튼을 띄운다.
- **카드 크게 보기** `shared/card-zoom.js`: 포커·블랙잭에서 카드 근처를 누르면 테이블의 카드를 줄별로
  크게 펼쳐 보여 준다(모두 뒷면인 줄은 뺀다). 드로우 포커에서 손가락으로 누르면 이 화면에서 바꿀 카드를 고른다.
- **효과음** `shared/sound.js`: Web Audio 로 mp3 를 불러 겹쳐 트는 `Sound` 클래스. 게임의 `js/sound.js` 는
  이를 상속해 소리 이름별 `{ volume, gap }` 표를 넘기고, 파일 없이 만드는 소리는 `prepare()` 에서 준비한다.
- **저장** `shared/storage.js`: `browserStorage()`, 예외를 삼키는 JSON 저장소 `JsonStore`, 검증용 `isInt`·`isTime`,
  항목별 최고 기록을 합치는 `mergeLowest`. 게임의 `js/save.js` 는 `JsonStore` 를 상속해 검증만 맡는다.
- **유틸** `shared/util.js`: 시드 난수 `createRng`, `shuffle`, `formatTime`, 프레임 보간 `damp`.
- **메뉴·HUD** `shared/ui.js`: 선택 버튼 묶음 `segmented`, 잠깐 뜨는 알림 `createToast`, 메뉴가 열릴 때
  키보드 사용자에게만 기본 버튼으로 포커스를 옮기는 `focusForKeyboard`.
- **공용 에셋** `shared/assets/`: 여러 게임이 같이 쓰는 카드·칩·텍스처·캐릭터·HDRI. 출처는 `shared/assets/CREDITS.md`.

## 3D 포커

종목은 시작 화면에서 고르거나 `poker/index.html?game=holdem` 처럼 주소로 지정한다.

| 종목 | `game` | 방식 |
| --- | --- | --- |
| 텍사스 홀덤 | `holdem` | 내 카드 2장 + 공용 카드 5장, 노리밋 |
| 오마하 | `omaha` | 내 카드 4장 중 정확히 2장 + 공용 카드 3장, 팟 리밋 |
| 파이브 카드 드로우 | `draw` | 5장을 받고 한 번 교환, 노리밋 |
| 세븐 카드 스터드 | `stud` | 7장 중 4장 공개, 앤티 방식, 공개 패가 높은 쪽이 먼저 베팅 |

- 시작 칩 1,000, 블라인드 10/20 (스터드는 앤티 10). 한쪽 칩이 모두 떨어지면 게임이 끝난다.
- 단축키: `F` 폴드, `C` 체크/콜, `R` 벳/레이즈, `Enter` 다음 핸드.
  드로우에서는 카드를 클릭하거나 `1`~`5` 로 바꿀 카드를 고르고 `Enter` 로 확정한다.
- 종목별 차이는 `poker/js/variants.js` 에 선언되어 있어, 종목을 추가할 때는 여기에 정의를 더한다.
- `poker/js/game.js`(규칙), `hand.js`(족보), `ai.js`(컴퓨터)는 렌더링과 분리된 순수 로직이고,
  `scene.js`(Three.js 씬)와 `main.js`(HUD·진행)가 이를 화면에 그린다.
- Three.js 는 CDN 에서 불러오므로 인터넷 연결이 필요하다.
- 3D 모델·텍스처·카드 이미지는 모두 CC0/퍼블릭 도메인 오픈소스 에셋이다. 출처는
  [`poker/assets/CREDITS.md`](poker/assets/CREDITS.md) 참고.

## 다트 301

- 시작할 때 컴퓨터와 대전 / 2인 대전(한 기기로 번갈아 던지기)을 고른다.
- 301점에서 시작해 한 턴에 다트 3개를 던지고, 남은 점수를 정확히 0 으로 만들면 이긴다.
  남은 점수보다 많이 맞히면 버스트로 그 턴의 점수가 무효가 된다. (더블 아웃 규칙은 없다.)
- 조준점은 포인터 주변에서 계속 흔들린다. 원하는 구역 위에 왔을 때 클릭(터치는 손을 뗄 때)해 던진다.
- `darts/js/board.js`(보드 규격·점수), `game.js`(규칙), `ai.js`(컴퓨터)는 순수 로직이고
  `scene.js`, `main.js` 가 화면을 담당한다.
- 던지기·꽂힘·고득점·버스트·차례·승패 효과음이 있다. `소리` 버튼이나 `M` 으로 끈다.
- `darts/index.html?debug` 로 열면 점수 계산에 쓰는 규격선이 보드 모델 위에 겹쳐 그려진다.
- 에셋 출처는 [`darts/assets/CREDITS.md`](darts/assets/CREDITS.md) 참고.

## 볼링

- 컴퓨터 또는 다른 사람(2인 대전, 한 기기로 번갈아 치기)과 번갈아 10프레임을 치는 텐핀 볼링. 스트라이크·스페어·10프레임 보너스 투구까지 표준 점수 규칙을 따른다.
  파울과 스플릿 표시는 없다.
- 투구는 세 단계다. 포인터(또는 `←`/`→`)로 공을 놓을 위치를 고르고, 좌우로 흔들리는 조준선과
  오르내리는 세기 게이지를 차례로 클릭(터치는 탭)하거나 `Space`/`Enter` 로 확정한다.
- 굴러가는 소리(합성), 핀 충돌(물리 엔진 충돌 세기에 따라), 거터·스트라이크·스페어 효과음이 있다.
  `소리` 버튼이나 `M` 으로 끈다.

## 메모리 카드

- 덮인 카드를 두 장씩 뒤집어 같은 동물끼리 짝을 맞춘다. 틀리면 1.1초쯤 보여 준 뒤 다시 덮는다.

  틀린 카드가 펼쳐져 있을 때 다음 카드를 바로 눌러도 된다(기다리는 시간을 줄일 수 있다).
- **2인 대전**: 한 기기에서 번갈아 한다. 짝을 맞추면 한 번 더, 틀리면 차례가 넘어가고, 짝을 더 많이 모은 사람이 이긴다.

  틀린 카드가 펼쳐져 있을 때 누르면 카드를 덮고 차례만 넘긴다. 한 판 더 하면 먼저 하는 사람이 바뀐다.

  으뜸 점수가 같으면 그 사람들만 연장으로 한 발씩 더 던지고, 5번 돌아도 같으면 비긴다. 한 판 더 하면 먼저 던지는 사람이 바뀐다.
- 화살을 던질수록 줄이 뒤로 물러난다(가까운 줄 2.5m → 가운데 줄 3m → 먼 줄 3.5m). 연장은 가운데 줄에서 던진다. 바람은 없다.
- 조작: 화면을 위로 밀어 올려(스와이프) 던진다. 민 길이가 세기(화면 높이의 45% 가 최대, 절반쯤이 알맞다), 기울기가 좌우 방향이다.
  화살을 든 손은 늘 조금씩 흔들려 놓는 순간의 흔들림만큼 방향·세기가 어긋난다. 누른 채 1초쯤 기다리면 차분해지고,
  5초를 넘기면 지쳐 다시 흔들리며, 먼 줄일수록 크게 흔들린다(손에 든 화살과 땅의 조준선에 보인다).
  키보드는 `←`/`→` 로 방향(`Shift` 미세), `Space` 를 누르고 있다 원하는 세기에서 뗀다. `M` 소리, `Esc` 메뉴.
- 던진 뒤에는 카메라가 화살을 따라 항아리로 다가가고, 촉이 입에 다다르면 잠깐 느린 화면으로 보여 준다.
- 물리(`tuho/js/physics.js`)는 1/1200초 간격의 강체 계산이다. 화살은 촉 쪽이 무거운 굵기 있는 막대이고, 깃이 날아가는 방향으로
  돌려세운다. 항아리와 귀는 놋쇠 벽 중심선을 돌린 회전체라 몸통·목·벌어진 입·안쪽 바닥이 거리 함수 하나로 계산되고,
  닿은 점마다 반발과 마찰 충격을 주어 테두리에 맞고 튕기거나, 목에 걸치거나, 미끄러져 들어간다. 멈춘 화살 촉의 자리로 판정한다.
  같은 던지기는 언제나 같은 결과다.
- `tuho/js/physics.js`, `game.js`(점수·차례·줄·연장), `ai.js`(컴퓨터: 겨눈 세기·방향에 실력만큼 떨림, 어려움은 따라잡기 어려우면 귀를 노림),

## 미니 골프

## 차 빼기

- 6×6 주차장에서 차를 앞뒤로 밀어 길을 터, 빨간 내 차를 오른쪽 벽의 출구(위에서 셋째 줄)로 빼내는 슬라이딩 블록 퍼즐.
  차(길이 2)와 트럭·버스(길이 3)는 놓인 방향으로만 움직인다. 내 차가 출구에 닿으면 출구로 달려 나가며 클리어.
- 한 차를 한 번 미는 것이 1수(몇 칸을 가든). 같은 차를 잇달아 밀면 한 수로 치고, 제자리로 되돌리면 그 수는 없던 것이 된다.
  최소 수 그대로면 별 3개, 최소 수의 1.5배(올림) 안이면 2개, 그 밖은 1개.
- 단계는 입문(최소 2~7수)·초급(8~13)·중급(14~21)·고급(22~30)·전문가(31~50) 12개씩 60개. 깬 단계 수보다 3단계 더 열려 있어
  막힌 단계는 건너뛸 수 있다. 단계별 최고 기록(가장 적은 수, 힌트를 썼는지)이 localStorage 에 남는다.
- **오늘의 퍼즐**: 날짜로 정한 시드로 게임이 그 자리에서 만든다(최소 14~26수, 같은 날이면 누구에게나 같은 퍼즐).
  만드는 데 0.3~1초쯤 걸려 Web Worker(`js/daily-worker.js`)에서 만들고, 그날 만든 퍼즐은 저장해 둔다. 연속 일수를 센다.
- 조작: 차를 눌러 놓인 방향으로 끌면 밀린다(막히면 그 앞까지만). 키보드는 `Tab`/`Shift+Tab` 차 고르기, 방향키로 고른 차 밀기
  (고른 차가 못 가는 방향이면 그쪽의 차를 고른다), `Z` 되돌리기, `R` 다시 시작, `H` 힌트, `M` 소리, `Esc` 단계 선택.
  힌트는 풀이기가 다음 한 수를 초록 자리로 보여 주고, 쓰면 그 판의 기록에 💡 가 붙는다.
- 풀이기(`unblock/js/solver.js`)는 차마다의 자리를 3비트씩 묶은 수 하나를 상태로 너비 우선 탐색해 최소 수 풀이를 찾는다.
- 단계 목록(`unblock/js/levels.js`)은 생성기로 미리 만든다. 저장소 루트에서

  ```sh
  node unblock/tools/generate.js          # 기본: --seed 2026 --climbs 24 --steps 1200 --per-tier 12
  node unblock/tools/generate.js --dry    # 파일을 쓰지 않고 난이도별 결과만 본다
  ```

  무작위 배치에서 닿는 모든 상태 가운데 출구에서 가장 먼 상태를 문제로 삼고(그래서 언제나 풀리고 최소 수도 안다),
  차를 빼고 더해 보며 더 어려워지면 받아들이는 언덕 오르기로 어려운 퍼즐을 찾는다. 일꾼 8개(worker_threads)가 시드를 나눠 돌리고,
  같은 모양은 합친 뒤 난이도마다 범위 안에서 고르게 골라(입문·초급은 차가 적은 판부터) 풀이기로 다시 확인해 쓴다.
  같은 설정이면 언제나 같은 목록이 나온다. 8코어에서 10여 분 걸린다. 단계 id 는 판의 해시라 목록을 다시 만들어도 같은 판의 기록은 이어진다.
- `unblock/js/game.js`(규칙·난이도·별), `solver.js`, `generator.js`(퍼즐 만들기·오늘의 퍼즐), `save.js`(기록·설정)는 순수 로직이고
  `scene.js`, `main.js`, `sound.js` 가 화면과 소리를 담당한다.

## 주차

- 내 차(빨간 세단)를 몰아 노란 칸 안에 반듯하게 세운다. 차체가 칸 안에 다 들어가고, 칸과의 각도 차이가 7° 안이고, 멈춘 채 1초가 지나면 주차 완료다.
  화살표가 그려진 칸은 그 방향으로 차 앞이 가야 한다(기능시험·평행 주차·막다른 골목은 후진으로 넣어야 한다).
- 14단계: 첫 주차 → 꺾어 들어가기 → 뒤로 넣기 → 기능시험 직각(T자)·평행 주차 → 사선 주차 → 양옆이 꽉 찬 칸 → 좁은 골목 → 지하주차장(기둥)
  → 도로변·왼쪽 평행 주차 → 막다른 골목 → 기둥 옆 좁은 칸 → 만차. 앞 단계를 깨면 다음 단계가 열린다.
- 주차된 차·기둥·벽·연석·콘에 닿으면 접촉 횟수가 늘고 화면이 흔들린다. 약 11 km/h(3 m/s) 넘게 부딪히면 사고로 실패하고,
  기능시험 두 단계는 세 번 닿으면 실격이다.
- 채점: 100점에서 접촉 1번에 10점, 기준 시간을 넘긴 2초마다 1점(최대 20), 기준보다 많은 전후진 전환 1번에 5점(최대 20),
  칸 가운데·각도에서 벗어난 만큼(최대 20)을 뺀다. 90점 이상 ★★★, 70점 이상 ★★, 나머지 ★. 단계별 최고 점수·별이 localStorage 에 남는다.
- 키보드: `↑`/`W` 전진, `↓`/`S` 후진(기어가 저절로 D/R 로 바뀐다. 반대로 구르는 중이면 먼저 멈춘다), `←`/`→`·`A`/`D` 핸들
  (누르는 동안 꺾이고 놓으면 가운데로), `Space` 브레이크, `Shift` 를 누르고 있으면 살살, `G` 기어만 바꾸기, `C` 시점, `V` 예상 궤적,
  `R` 다시 시작, `Esc` 단계 선택, `M` 소리.
- 화면: 왼쪽 아래 핸들을 끌어 돌린다(270° 가 끝, 손을 떼도 그대로, 두 번 톡 치면 가운데로). 오른쪽 아래 가속·브레이크 페달은 누르고 있는
  동안 밟히고 가속은 오래 누를수록 깊어진다. 그 위의 D/R 를 누르면 기어가 바뀐다. 두 손가락(마우스는 휠)으로 확대·축소.
- 시점: 위에서(차와 칸을 함께 따라감) / 3인칭 / 3인칭+후방(R 기어면 차 앞 위에서 뒤쪽을 본다). 예상 궤적은 지금 핸들 각도로 기어 방향
  5m 를 차 폭만큼 그린다(1m 빨강, 2m 노랑). 가는 쪽 장애물이 1.5m 안이면 주차 감지기가 삐삐 울리고 거리가 뜬다.
- 차는 자전거 모델(축간거리 2.23m, 최대 조향 31.5°, 뒤축 회전 반지름 약 3.6m)로 움직이고, 충돌은 차체와 장애물을 방향 있는 사각형(OBB)으로
  보고 분리축으로 판정한다. 1/120초 고정 간격이라 같은 입력은 같은 결과다.
